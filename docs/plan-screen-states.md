# Plan: what the app shows when things go wrong, are empty, or are old

Written Oct 1, 2026. Status after v5.16: built are the 404 page, the start-up timeout, the phone bad-link notice, print styles, the hosted-site offline notice, and the tab icon. Still open: the desktop bad-link notice, the empty-result pass, storage-blocked and copied messages, the last-good-update line, and the Tell us button.

The goal: a resident never meets a blank screen, a browser error page, or a dead end. Every state says
what happened in plain words and offers one clear next step. It follows the same voice rules as
docs/plan-guided-stories.md: warm, direct, no jargon, no small grey text for anything that matters.

## Where we stand

| State | What we have | What is missing |
| --- | --- | --- |
| First load | A "Loading the Cleveland Civic Graph" screen with reduced-motion handling, and a message when JavaScript is off | If the app fails to start (an old browser, a blocked script), the loading screen stays forever |
| A screen crashes | Error boundaries around every tab, panel, overlay, desktop page, and the whole app, with Try again, Go to the start, Reload, and switch layout | No way for a resident to tell us. The correction intake is not built |
| Page not found (404) | Nothing. The hosted site has no 404 page, so Vercel's plain default shows | A friendly page with the three starter journeys and a search |
| A bad or old link | A link with an unknown room or record opens the Today screen with no explanation | A short notice: "We could not find that page. Here is the start." Records Legistar later removes need their own message |
| Empty results | Good copy in places (a ward with no money found says missing here means none was found, not that nothing happened) | A full pass over every search, filter, and list so none ends with a bare blank. Each says what was searched and offers a next step |
| Updated and old data | An Updated chip with the time, "pulled N days ago", a stale warning at 3 days or more with a link to the official source, and What's new | The federal data and any future source need their own freshness line. Residents are not told when a nightly run failed and old data was kept |
| Missing or not applicable record | Strong. Missing, partial, contested, and not applicable are shown honestly | Keep it that way in the federal graph |
| Offline or slow connection | The single-file copy works fully offline | The hosted site has no offline support, so a visit with no signal shows the browser's error page. A small "you appear to be offline" notice, and later a cached shell |
| Storage blocked (private browsing) | Local storage is used in 8 places, and the ballot reports storage errors | Check that every use fails quietly and tells the person their choices will not be remembered |
| Saved or copied | Not audited | A short confirmation when a letter is copied or a choice is saved, announced to a screen reader |
| Print and save | No print styles at all | A clean print version of a record, a story, and "who represents me". Easy mode promises "save or print this page" |
| Fetch failed in the nightly job | Old data is kept and GitHub emails the owner | A visible "last good update" line so the site never claims to be fresher than it is |

## Phase 1d: screen states (about one session, after quiet text, before Easy mode)

Do the cheapest and most visible fixes first:

1. A built 404 page in site/, with the three starter journeys and a search. Generated by build.py so it matches the app's look in both styles.
2. A start-up timeout: if the app has not drawn by about 10 seconds, the loading screen changes to "This is taking longer than usual", with Reload and a link to the offline copy.
3. A notice for unknown room and record links, in both layouts.
4. An empty-result pass over search, filters, and lists, with one next step each.
5. Print styles for records, stories, and the "who represents me" screen.
6. An offline notice on the hosted site.
7. Storage-blocked and copy-confirmed messages, announced to screen readers.

Done when: each state above has a screen, each is checked at phone and desktop width in Bento and
Original, a screen reader announces the change, and a short list in STATE-OF-BUILD.md says which states
exist and which do not.

## Later

- A Tell us what is wrong button on the error and 404 screens, once the correction intake exists. It must go through review and never edit the graph directly.
- A cached app shell for the hosted site, built carefully so a visitor never gets an old version after a deploy.
- Each new source, including the federal ones, ships with its own loading, empty, stale, and failed states before it goes live.

## Rules

Both styles, both layouts, no em dashes, no left accent stripes on alerts (use dots or tinted
backgrounds), nothing personal in links or requests, plain English, and a clean rebuild with the hash
recorded.
